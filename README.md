
# toolkit

Python-пакет с командной строкой (CLI): калькулятор арифметических выражений и конвертер величин.

Лабораторная работа 1.

## Требования

- Python >= 3.10

## Установка

Из корня проекта (`lab_01`):

```bash
python3 -m pip install -e ".[dev]"
```

## Запуск

```bash
python3 -m toolkit --help
python3 -m toolkit calc "2+3*4"
python3 -m toolkit convert 1000 --from mm --to m
```

Примеры:

```bash
python3 -m toolkit calc "10 / 4"
python3 -m toolkit calc "-2 * -3"
python3 -m toolkit calc "(2+3)*4"
python3 -m toolkit convert 1.5 --from kg --to g
python3 -m toolkit convert 0 --from c --to f
```

## Калькулятор

Поддерживается:

- целые и вещественные числа
- операции `+`, `-`, `*`, `/`, `//`, `%`
- унарный `+` и `-`
- пробелы между токенами
- приоритет `*` `/` `//` `%` над `+` `-`
- скобки `()`

Ограничения:

- `//` и `%` — только для целых чисел
- `eval` / `exec` не используются

### Как устроен разбор

Калькулятор не использует eval / exec. Разбор и вычисление идут в четыре этапа:

1. Токенизация

Функция tokenize_fsm проходит по строке посимвольно и разбивает ее на токены:

- числа (int / float, с учетом унарного + / -)
- операторы +, -, *, /, //, %
- скобки ( и )

Автомат имеет состояния START, NUMBER, OPERATOR, AFTER_NUM

Пробелы игнорируются, унарный плюс и минус обрабатываются отдельно с помощью переменной unary_sign и flag, // распознается как один оператор

На этом этапе ловятся многие синтаксические ошибки (ConsecutiveOperatorsError, EmptyExpressionError, InvalidCharacterError, MissingOperandError, TooManyDotsError)

2. Валидация

Функция validate проверяет готовый список токенов на:

- баланс скобок
- отсутствие пустых скобок ()
- корректность соседних токенов (число и число, число и открывающая скобка, закрывающая скобка и число, оператор перед закрывающей скобкой, оператор сразу после открывающей скобки)

Если что-то не так - выбрасывается соответствующая ошибка

3. Перевод в обратную польскую запись (RPN)

Алгоритм обрабатывает список токенов:

- числа сразу идут в выход
- операторы кладутся в стек с учетом приоритета (*, /, //, % выше, чем + и -)
- скобки влияют на порядок выталкивания операторов из стека в выход

В результате получается список, в котором сначала идут числа, потом операции с учетом приоритетов (скобки отсутствуют)

4. Вычисление через стек

Функция eval_RPN проходит по RPN-записи:

- числа кладет в стек
- встретив оператор, достает два операнда, выполняет операцию и кладет результат обратно в стек

Специальные правила:
- деление на ноль вызывает ошибку DivisionByZeroError
- // и % разрешены только для целых чисел, иначе ошибка

В конце в стеке остается один элемент - результат вычисления выражения

## Конвертер

- длина: `mm`, `cm`, `m`, `km`
- масса: `g`, `kg`
- температура: `c`, `f`, `k`

Правила:

- регистр единиц не важен (`MM` = `mm`)
- нельзя конвертировать между разными группами (`kg` -> `m` — ошибка)
- температура ниже абсолютного нуля запрещена  
  (`0 K`, `-273.15 C`, `-459.67 F`)

## Ошибки

CLI при ошибке:

- пишет сообщение в stderr
- завершается с кодом 2

Успешная команда завершается с кодом 0.

Примеры ошибок:

- пустое выражение
- недопустимый символ
- два оператора подряд
- пропущенный операнд
- деление на ноль
- неизвестная единица
- несовместимые единицы
- температура ниже абсолютного нуля
